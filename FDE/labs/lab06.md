# 06. Coding Agent Hill Climbing

## 목표: 모델을 gemini-3.1-flash-lite로 고정한 채, 도구와 시스템 프롬프트만으로 성능을 올립니다.

##### 핵심 내용
- 모델이 같아도 하네스(도구, 컨텍스트, 검증) 가 능력을 결정합니다.
- 진단 대상은 태스크의 버그가 아니라 에이전트의 결함입니다. 예를 들면 코드 검색을 못 했다거나 수정 후 직접 실행해 검증하지 않았다는 식입니다.
- 수정은 agent.py만 가능하고 tasks/는 건드릴 수 없습니다. 특정 태스크에 맞춘 하드코딩은 최종 채점에서 자동 실패합니다.

##### 랩 흐름
1. Antigravity CLI를 설정하고 .venv를 구성합니다.
2. python eval.py로 기준선을 잽니다. 결과가 들쭉날쭉하며 평균 절반 미만을 해결합니다.
3. repro.sh와 trajectory로 실패 1건을 직접 분석해 /submit-task-diagnosis로 제출합니다.
4. 나머지 실패는 Antigravity에 진단만 맡깁니다. 이 단계에서 파일을 수정하면 안 됩니다.
5. agent.py를 개선하고 eval을 반복해 대부분의 실행에서 5개 중 4개 이상 통과시킵니다.
6. /grade-my-agent로 최종 제출합니다.
